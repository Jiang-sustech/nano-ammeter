# 用 MATLAB 拟合物理常数 —— 操作指南

> 面向 MATLAB 初学者。从**测数据**到**把结果发给固件**，一步不落。

## 你要做的事（一句话）

测一串**已知电流**，让 MATLAB 反推出式(6) 里的三个常数：`M`（含电平移位增益的
等效电容）、`I₊`、`I₋`。

$$
I=\frac{M\,(V_{o1}-V_{o2})}{(m+n)\,T}-\frac{m\,I_{+}+n\,I_{-}}{m+n}
$$

---

## 开始之前，先确认三件事

| | |
|---|---|
| MATLAB 装了 | 打开能看见窗口就行 |
| 板子烧了 `physics_exp_test` | 结果行要带 `RAW` 段 |
| 有一个能给出**已知电流**的源 | 源表，或者"电压 ÷ 高阻" |

> ⚠️ **已知电流必须 ≥ 1 nA。** 式(6) 是模式一的公式；低于 1 nA 固件会自动切到
> 小电流模式，那条路**不出 `RAW` 段**，采了也用不上。

---

## 第一步：采数据（每个已知电流跑一次）

打开命令提示符 / Git Bash，进到仓库目录，然后：

```bash
python tools/nanoammeter_capture.py COM7 --no-noise --true=25.0
```

三个参数的意义：

| 写法 | 换成 |
|---|---|
| `COM7` | **你的串口**。不确定就跑 `python -c "import serial.tools.list_ports as p; print([x.device for x in p.comports()])"` |
| `--no-noise` | 保持写。`physics_exp_test` 没有底噪指令，不加这个会干等 90 秒然后失败 |
| `--true=25.0` | **这次输入电流的已知真值，单位 nA** |

> **`--true=` 必须写成等号形式。** 写成 `--true -40` 的话，那个 `-40` 会被当成
> 串口名。负数尤其要注意。

跑完当前目录会多出 `raw_日期_值nA.npz`、`.png`、`.log` 三个文件。

**每个已知电流跑一次。** 建议：

- **正负都要有** —— 只有同号的数据，`I₊` 和 `I₋` 分不开
- **跨整个量程** —— 1 nA 到 45 nA 都覆盖到
- **每个量程几十组** —— 太少的话拟合结果不稳

## 第二步：汇总成 CSV

```bash
python tools/make_fit_csv.py -d . -o fit_data.csv
```

它会打印：

```

  文件                                     I_true(nA)      m+n    c2-c1
  raw_09_13_+25.0nA.npz                       25.0000     6250     -312
  raw_09_13_-40.0nA.npz                      -40.0000     6250      108

  raw_09_13_old.npz                          没有 RAW 段 (老固件?)
  raw_09_13_+5.0nA.npz                       没记已知真值 (采的时候没加 --true=)
```

**逐行核对这张表。** 如果看到"没记已知真值"，说明那几次采集忘了加 `--true=`，

**这一步绝对不要手工抄。** 每个文件要取 4 个数、还要和当时的已知电流严格配对，
抄错一行整条拟合就歪了，而且**歪得不明显**。

## 第三步：在 MATLAB 里跑

### 方式 A：图形界面（推荐初学者）

1. 双击打开 MATLAB（**首次启动要 30~60 秒**，正常）
2. 看左边「当前文件夹」那一栏，点进去，导航到 `nanoammeter_repo\tools`
3. 看下方「命令行窗口」，`>>` 后面**输入这一行，回车**：

```matlab
fit_constants('C:\完整路径\fit_data.csv')
```

> 路径要写**完整的**。偷懒的办法：在资源管理器里按住 Shift 右键点那个 CSV，
> 选「复制文件地址」，粘贴进来，把首尾的引号留好。

### 方式 B：命令行（不进图形界面）

在仓库根目录：

```bash
matlab -batch "cd('tools'); fit_constants('../fit_data.csv')"
```

### 先跑一遍自测（可选，但推荐）

想确认脚本本身没坏，跑这个（用合成数据，**不需要任何硬件**）：

```bash
matlab -batch "cd('tools'); test_fit_constants"
```

看到 `############ 全部通过 ############` 就对了。

## 第四步：读输出

```
===== 拟合结果 (n=12 组) =====
  M    = +3.005319e-10  ± 1.4e-12   (0.452%)   期望 |M| ≈ 3.030e-10
  I-   = -50.2551 nA  ± 0.0002 nA  (0.000%)   独立实测 -50.2550 nA
  I+   = +50.2320 nA  ± 0.0002 nA  (0.000%)   独立实测 +50.2320 nA
  RMSE = 1.0676 pA
  条件数 cond(A) = 20

  ---- 杠杆对比 (决定各自能被定到多准) ----
    端点项 M·a1  的跨度 =    62.61 pA
    计数项 b2·a2 的跨度 = 59986.73 pA
```

| 看什么 | 怎么判断 |
|---|---|
| **`±` 后面的标准误** | **这个才是重点**。误差 0.45% 就是"这个数只准到这个程度" |
| **`期望 \|M\| ≈ 3.030e-10`** | 拟合值应在它附近。差一个数量级（比如 3.3e-11）说明 CSV 里的码列取错了 —— 那正好是把电平移位增益除反的样子 |
| **`独立实测`** | 和 `V/R` 量的值对照。**对不上说明模型或数据有问题** |
| **`RMSE`** | 应和仪器的分辨力同量级（模式一约 1 pA）。远大于 1 pA 说明数据有离群点 |
| **`条件数`** | 大于 100 会**自动报警** —— 数据覆盖太窄或全是同号 |
| **`杠杆对比`** | 见下 |

### 杠杆对比：为什么脚本劝你别用 `M`

```
计数项跨度 60 nA   -> I+/I- 定到 0.0004%
端点项跨度 62 pA   -> M 只能定到 ~0.45%
```

**差 960 倍。** 原因是端点项本来就只是"电荷平衡之后剩下的那一小截"，
量级只有几十 pA，而计数项扛着整个 60 nA。

**所以：**

- ✅ **`I₊` / `I₋` 就用这个拟合的结果**
- ❌ **`q`（也就是 `M`）不要用这个拟合** —— 用专门的"灌已知电流"测量：
  参考断开、灌进去、积已知时间、读码差，`q = I·T/Δc`。那里 `Δc` 能跑满整条
  斜坡，杠杆大一个量级，重复 N 次还能再降 `√N`

### 自动弹出的四张图

| 图 | 看什么 |
|---|---|
| 左上 拟合 vs 已知 | 点应贴着 45° 虚线。**在小电流那头散开是正常的**（分辨力限制） |
| 右上 残差 | 应围绕 0 随机散布，**不能有喇叭形或弯曲** |
| 左下 相对残差 | 小电流处偏大是正常的（相对误差本来就大） |
| 右下 拟合出的参考电流 | 两根柱应差不多高（±50 nA 附近） |

**残差图出现喇叭形或弯曲 = 模型有问题，别急着用结果。**

## 第五步：把结果发给固件

脚本结尾会直接给出一行现成的指令：

```
      Q15133,50232,-50255
```

**这一行直接发给板子**（用网页控制台，或任意串口终端），固件会回：

```
CAL Q SET 15133,50232,-50255
```

就存进 Flash 了，**掉电不丢**。想确认，发一个裸 `Q` 查询：

```
CAL Q 15133,50232,-50255
```

> `q` 这一项如果是用上面说的**专门测量**得到的，就把那次的数字替换掉 `Q` 里的
> 第一个数，其余不变。

## 常见错误

| 报错 | 原因 |
|---|---|
| `未定义函数或变量 'fit_constants'` | 当前文件夹没在 `tools` 里。用 `cd` 过去，或者把 `tools` 加进路径 |
| `fit_constants:col 缺列 xxx` | CSV 表头不对。应该正好是 `I_true,c1,c2,m,n` |
| `fit_constants:code c1 超出 16 位码域` | CSV 里混进了别的列，或者分隔符被 Excel 改过 |
| `!! 条件数偏大` | 数据覆盖太窄 / 全是同号。补测几组 |
| 中文显示成方块 | MATLAB 主页 → 预设 → 字体，换一个支持中文的字体 |
| 命令窗口输出乱码（用 `-batch` 重定向时） | Windows 下 MATLAB 输出是 GBK，用记事本打开，或 `iconv -f gbk -t utf-8` |

## 为什么值得这么做（而不是用老的 a/b 分段拟合）

| | `a/b` 分段拟合 | 拟合物量参数 |
|---|---|---|
| 参数个数 | 3 段 × 2 = **6 个** | **3 个，全量程共用** |
| 参数含义 | 经验增益/偏置，黑盒 | **物理量，能和独立测量对照** |
| 段与段之间 | 各自为政，接缝处跳变 | 自然连续 |

拟合出来的 `I₊`、`I₋` **每一个都能用万用表独立验证** —— 对不上就说明有问题。
`a/b` 做不到这一点。
