### 烧录

```bash
openocd.exe -f <...>/scripts/interface/stlink-v2-1.cfg \
            -f <...>/scripts/target/stm32l4x.cfg \
            -c "adapter speed 2000" \
            -c "program <elf> verify reset exit"
```

OpenOCD 在 `C:\Users\40512\STM32Toolchain\openocd\bin\`。
**克隆 ST-Link 必须用 `stlink-v2-1.cfg`**，脚本路径要写全。

串口烧录备选：`tools/uart_flash.py`（AN3155 Bootloader，需 BOOT0 拉高复位）。

### 读内存 / 看状态机

```bash
arm-none-eabi-nm nano_ammeter.elf | grep <符号>   # 查符号地址
# OpenOCD 里:
mdw <地址>                                        # 读 32 位字
```

halt 后读 PC：

| PC 范围 | 含义 |
|---|---|
| `0x0800xxxx` | 在跑固件 |
| `0x1fffxxxx` | 停在系统 bootloader |

### VTref 假警报（克隆 ST-Link）

**克隆 ST-Link 没有真正的 VTref 检测脚**，OpenOCD 报的 `Target voltage`
是内部悬空的垃圾值，永远修不好也不用管。

出现 `Error: target voltage may be too low` 时**先看 SWD 有没有识别核心** ——
只要出现 `Cortex-M4 r0p1 processor detected` + `6 breakpoints, 4 watchpoints`，
就说明芯片有电、链路可靠（同一轮里那个读数会在 0.88/1.03/1.24/1.32V 之间乱跳，
稳定的轨不会这样）。

> **不要因为这句话去推翻已有的诊断。万用表读数为准。**

## 二、已验证的工程结论（代码里可查，不是诊断）

### ADC 时钟必须用 SYSCLK

本工程 HAL 版本对 L431 的 PLLSAI1 路径有缺陷（L431 PLLSAI1 无 M 分频器，
HAL 写出非法配置且**不使能 PLL**）→ ADC 无时钟 → 转换永不完成 →
中断内轮询死锁、采样恒 0。

**已改为 `RCC_ADCCLKSOURCE_SYSCLK`（80MHz，在 L431 fADC 上限内）。**
见 `adc.c` 的 `HAL_ADC_MspInit` 注释。

### 中断内不能依赖 `HAL_GetTick`

TIM6 中断优先级 0 高于 SysTick 的 15 → 中断执行期间 SysTick 无法抢占 →
tick 停走 → 任何依赖 tick 的超时轮询变成死循环。

`Adc_ReadRaw()` 与 `ads8866.c` 全部改成**寄存器级轮询 + 循环计数守卫**。

### 守卫的写法（本工程踩过）

```c
guard = 200000U;
while (((REG & FLAG) == 0U) && (guard != 0U)) { guard--; }
if (guard == 0U) { /* 超时 */ }
```

**绝不能写 `guard-- > 0U`** —— 那样最后一次判断会多减一次，下溢成
`0xFFFFFFFF`，后面 `guard == 0U` 的超时判断永远不成立，守卫形同虚设；
转换一旦不完成就是死循环。

### L4 校准函数会关掉 ADC

`HAL_ADCEx_Calibration_Start()` 结束后 ADEN=0，寄存器级读取前需重新使能并等
ADRDY。见 `Adc_Init()`。

### STM32L4 是经典 SPI

只有 `CR1/CR2/SR/DR`，**没有** H7 的新 SPI（`CFG1/CFG2`）。
16 位帧要 `CR1.DFF` 或 `CR2.DS=0xF`。

### ADS8866 用 3 线 CS 模式

CONVST 上升沿时 **DIN 必须为高**，否则芯片进菊花链模式。
因此每次传输都发 `0xFFFF` 维持 DIN 高。

并且：CONVST 拉起之前必须先写过一次 SPI DR（让 DIN 变高），
否则第一次 CONVST 时 DIN 还是低 → 进菊花链 → 读回 0x0000/0xFFFF 之类的
无效码，平白给坏读计数记上一笔假故障。见 `ADS8866_Init()` 的注释。

### 电平移位反相映射

`V_ad = 1.55 − 0.33·V_o`（反相求和器，论文确认）。

阈值码（3.3V / 65536）：`code_lower = 2602`↔V_o=+4.3V，
`code_upper = 58963`↔V_o=−4.3V，`code_zero = 30782`（V_o=0）。

> **这几个阈值码是用标称的 `LEVELSHIFT_GAIN = 0.33` 和 `LEVELSHIFT_V_ADC_ZERO = 1.55`
> 算出来的，两个都没实测过。**
>
> 影响范围有限：式(6) 里 `V_ADC_ZERO` 在端点差里**约掉**，`GAIN` 被吸收进可标定的
> `q` —— 所以**它们不影响测量精度**。真正受影响的只是"实际摆幅到底是不是 ±4.3 V"，
> 而那只决定 bang-bang 的周期长度。
>
> 想验证的话：看 `B` 回传波形的 min/max 是否 ≈ 2602 / 58963。**对不上不影响结果，
> 只是说明摆幅不是设计值。**

### 内置 ADC 的码域（容易搞错）

内置 ADC 是 **12 位**，写进缓冲前做了 `raw << 4` 归一化到 16 位域
（`adc.c`：`adc_last_raw = (uint16_t)((uint32_t)raw << 4);`）。后果：

- **所有码值都是 16 的倍数**，有效分辨率 16 码（不是 1 码）
- **满量程在 16 位域是 65520**（= `4095 << 4`），**不是 65535**
- ADS8866 是真 16 位，满量程才是 65535

所以看到 `65520` 不是异常值，是内置路撞满量程。

## 二·补、HSE 晶振（2026-09-12 实测，推翻旧结论）

### 结论：晶振是好的，可以用；但 PLLM 不能取 1

| 配置 | 结果 |
|---|---|
| SYSCLK = MSI（原配置） | 正常 |
| SYSCLK = HSE **直连**（不过 PLL） | 时钟切换成功，但串口读不出 |
| SYSCLK = HSE + PLL，**PLLM = 1**，N = 20 | **INVSTATE HardFault** |
| SYSCLK = HSE + PLL，**PLLM = 2**，N = 40 | **正常工作** |

**晶振本身没问题**：置 `HSEON` 后 `RCC_CR.HSERDY` = 1；示波器实测 7.999989 MHz
（偏差 1.4 ppm）。**旧记录里"板上 8 MHz HSE 不起振、必须用 MSI"是错的。**

**`PLLM = 1` 这个坑值得记**：HSE 8 MHz ÷ 1 = 8 MHz VCO 输入，**在 4–16 MHz
规格内、合规**；查 ST 文档与 erratum 都没找到禁止它的条款（只找到 CubeMX 一个
"生成的代码漏写 PLLM、默认成 8"的旧 bug）。但实测就是崩：

```
CFSR = 0x00020000  (UFSR.INVSTATE —— 指令流被破坏)
HFSR = 0x40000000  (FORCED, 升级为 HardFault)
LR 落在 Measurement_Task 调 MeasurementState_Process 之后
```

换成 **PLLM = 2 / PLLN = 40**（VCO 输入 4 MHz，输出仍是 160 MHz / PLLR=2 → 80 MHz）
就完全正常。

**没有解释，只有实测**。以后 L4 配 HSE 建议直接用 PLLM ≥ 2。

验证方式（不改固件）：
```
mww 0x40021000 0x00010000   # 置 HSEON
mdw 0x40021000              # bit17 HSERDY=1 即起振
mdw 0x40021008              # RCC_CFGR: bits3:2(SWS) = 0b10 表示 SYSCLK 已切 HSE
mdw 0x40021000              # RCC_CR: bit24(PLLON) 确认 PLL 开关状态
```

## 二·补二、CAL_BANG 标定固件从来没工作过（2026-09-12 发现并修复）

TIM6 中断的路由写错了：

```c
#if CAL_MODE == CAL_NONE
    Current_Process();
#else
    CalMode_Tick();     /* 标定固件: 节拍路由到标定逻辑 */
#endif
```

而 `CalMode_Tick()` 里只有 `CAL_ZERO` 的代码，`CAL_BANG` 分支是空的 ——
注释还写着"CAL_BANG: 采样由 Current_Process 完成"，**但那条路根本没被走到**。

后果：电压缓冲永远填不满、`finish_flag` 永远不置位、`CalBang_Report` 永远不执行。
**烧 CAL_BANG 固件后串口一行都不出。**

**这是长期存在的 bug**：`nano_ammeter` 与更早的 `中间测试/OLED_SH1106` 里都是同一份
代码，也就是说这个标定固件从来没有出过数据。

修法 —— 只有 CAL_ZERO 需要走自己的逐拍累加：

```c
#if CAL_MODE == CAL_ZERO
    CalMode_Tick();
#else
    Current_Process();
#endif
```

修好后实测（无输入，参考电流交替）：

```
CAL BANG: m=3121 n=3129 VPP=+8.75V MIN=2080 MAX=59440 I=-0.026nA
```

逐项核对全部符合设计：`m+n = 6250`、VPP 8.75V（设计 8.6V + 过冲）、
MIN/MAX 比阈值高/低约 515 码（正好是一拍的路程：500V/s × 160µs = 525 码）。

## 二·补三、参考电流的共模偏移以 1:1 进入读数（2026-09-12）

把补偿项按共模/差模拆开（令 `I₊ = I + d`，`I₋ = −I + d`）：

```
comp = (m·I₊ + n·I₋)/N = [(m−n)·I + (m+n)·d] / N
                           └─ 差模, 8.04 pA/计数   └─ 共模, 系数 (m+n)/N ≈ 1
```

**共模偏移 `d` 无衰减地进入每个读数。** 实测（短接积分节点 + 万用表量参考电阻压降，
R = 99.48 MΩ）：

```
V+ = 4.99703 V   V- = -4.99938 V     对称性差 0.047%
I₊ = +50.232 nA  I₋ = -50.255 nA
d  = (I₊ + I₋)/2 = -11.5 pA          <-- 直接加到每个读数上
```

参考电流只差 0.047%，但补偿项从 −56 变到 −68 pA，而模式一总读数才 20 pA ——
**放大了一百多倍**（因为补偿项是两个大数相减）。

**这是本架构的固有弱点**：I₊/I₋ 的温漂会 1:1 传进读数，是报告 4.7 节
不确定度预算里权重最大的一项；标定时**必须分别测两个极性**。

## 二·补四、分辨力实测（2026-09-12）

用 09-11 实采数据 + 二阶差分/MAD 估单点噪声：

| | 单点噪声 |
|---|---|
| 内置 ADC | 48.4 码 |
| ADS8866 | 49.0 码 |

**两种 ADC 噪声一样** —— 说明噪声来自模拟前端（积分器 + 电平移位），不在 ADC 里。

| 模式 | 单次分辨力 |
|---|---|
| 模式一（1 秒窗口，端点单点采样） | **~1.0 pA** |

## 二·补五、模式一的 `T=` 一直报 0ms（2026-09-12 发现并修复）

`measurement_state.c` 里 `measurement_ticks` **只在转入小电流模式那个分支被
赋值**，模式一那条路径从头到尾没碰过它，于是 `MeasurementState_GetTicks()`
恒返回初值 0 —— 每个模式一结果行都是 `T=0ms`。

后果不是"少个字段"，是**报告里 `I = C·ΔV/T` 的 T 直接错**（README 白纸黑字
写着模式一固定 1000ms，实际报 0）。修法是在模式一取结果处显式赋值：

```c
measurement_ticks = Current_GetSampleCount();   /* 恒为整窗 6250 拍 */
```

**教训**：这种"某个变量只在一条分支里被写"的 bug，编译器不会说话，
测试不跑那条路径也看不见。凡是结果行里出现的量，都要问一句
"它在**这条**分支上被赋过值吗"。

## 二·补六、`EN=0` 不是"0 A"，是 Hi-Z（2026-09-12 发现，**待实测 τ**）

### 现象

ADG1219 是单刀双掷：`EN=1` 时 A/B 二选一（+5V 或 −5V）；`EN=0` 时**两个都断**，
100 MΩ 那一端**浮空**，不是被拉到 0 V。

示波器实测：`+5 ↔ −5` 切换是正常方波；而 `0 ↔ +5` 时**上升沿正常、下降沿指数衰减**。

**不对称是必然的**：接通时开关的通态电阻很小、瞬间把节点强拉到 ±5V；断开后没有任何
主动驱动，只有 `R=100MΩ` 把那个节点的寄生电容 `C_p` 慢慢泄放到虚地：

```
i(t) = (V_n / R) · e^(−t/τ)        τ = R · C_p
总电荷 Q = C_p × V_n
```

**所以程序绝不能把 `EN=0` 当成"精确的 0 A 参考"。**

### 哪些地方受影响

四处**"复位后做纯积分"**——它们全都靠 `EN=0` 当 0 A：

| 位置 | 用途 |
|---|---|
| `SmallI_Start`（小电流模式） | 复位后纯积分 1 pA ~ 1 nA |
| `Noise_Start`（底噪） | 复位后纯积分 |
| `CalMode_Start`（CAL_ZERO） | 复位后纯积分 |
| `HardIntegral_Start`（模式二上积相，仅 `nano_ammeter`） | 复位后纯积分 |

**模式一不受影响**——它在窗口里只在 ±I_ref 之间切换，**从不进 `EN=0`**。

### 量级

`τ = 100MΩ × C_p`，`Q = C_p × 5V`，而 1 码 = 1.526e−14 C：

| `C_p` | `τ` | 总电荷 | 折合码 |
|---|---|---|---|
| 0.1 pF | 10 µs | 0.5 pC | 33 码 |
| 1 pF | 100 µs | 5 pC | 328 码 |
| **10 pF** | **1 ms** | **50 pC** | **3277 码** |
| 100 pF | 10 ms | 500 pC | 32770 码 |

**`C_p` 现在没人知道**——而它决定后面所有选择。

> ⚠️ **示波器量不准**：探头自身就有 10 pF 量级，会盖过板上的 `C_p`、把 τ 放大十几倍。
> 必须用别的办法。

### 怎么量 `C_p` / τ（下次上板）

用本仪器自己——它的 ADC 就是干这个的：

```
1. 拉回到接近 0V（参考接通）
2. ADG_Disable() 断开参考        <- 这一瞬注入 C_p × 5V
3. 立刻连续采样（每 160µs 一点），采几百点
4. 那段电压是「台阶 + 指数衰减」-> 拟合出 τ
   C_p = τ / 100MΩ,  总电荷 = C_p × 5V
```

判据：**τ 与 160 µs 的比较**

- `τ ≪ 160 µs`（`C_p` ≲ 0.1 pF）→ **无事**，四处纯积分模式都不用动
- `τ` 是 ms 量级 → 必须处理（见下）

### 处理方案（等 τ 出来再定）

| | 做法 | 代价 |
|---|---|---|
| **软件** | 拉回后等 `> 5τ` 再取起点（把 `SI_SETTLE_TICKS` 按实测 τ 定） | 只治标；大电流时 T 短、τ 相对更长 |
| **硬件** | 让 `EN=0` 接**真正的 0V**（换三掷开关，或加一路开关到地） | 要改板。**唯一能让"0V 参考"变成真的办法**，且一次解决四处 |

### 连带影响：`q` 的标定方法必须换

原定的 `q` 测法是"**参考断开** + 灌已知电流 + 积分"——**"参考断开"就是 `EN=0`**，
暂态会直接混进 `Δc`：

```
暂态 50 pC（C_p=10pF） -> 3277 码
信号 400 pC（50nA 积 8ms） -> 26212 码
误差 = 12.5%          <- 会整条传播到所有结果
```

**改用 `I₊` 自标**：把 ADG **固定在一个极性、关掉 bang-bang**，积 M 拍：

```
q = I₊ · (M · 160µs) / Δc
```

全程不进 `EN=0`，完全避开暂态；而且 `I₊` 走现成的参考通路，不引入新节点新电容。

**这需要加一个"固定极性积分"的固件模式（现在没有）。** 同一个模式还能顺便量 τ 和
参考电流的对称性。（`I₊` 自标的 `q` 只能把仪器做成**比值仪器**——精度锚在 `R` 上，
见「参考电流的共模偏移」一节）

### 附带结论：待测电流什么时候接

```
S 指令 -> 拉回相（约 10ms，最坏 400ms）-> 窗口 1.000s -> 出结果
```

**待测电流必须在整个拉回相期间就接好**——因为拉回相本身就受它影响
（净电流 = I_ref − I_x，决定拉回多快）。中途接入会让起点不可预期。

## 三、硬件链路（⚠️ 仅对本版硬件有效）

> 下面这些接线与器件细节是**这一版硬件**的实际情况。作者开源时会发布
> 修正后的硬件版本，届时以新版为准。

### OLED

- 屏幕 HS13L01（汉昇，128×64，SH1106，带字库芯片）
- 接线：**PB13=SCL、PB15=SDA、PB14=DC、PB12=CS1**；
  SPI2 模式 0、2.86MHz（规格上限 3.3MHz）。FS0 悬空、CS2 接 3V3 禁用字库
- **初始化序列必须含电荷泵使能**：`0xAD,0x8B`、`0x33`(VPP 9V)、`0xD9,0x1F`、
  `0xDB,0x40`。早期记录说原 SH1106-master 驱动缺这几条是屏幕不亮的根因

### 供电

台式电源 3.3V 或 ST-Link 供电都可行，两条路都稳定。

### 时钟

固件用 **MSI 内部时钟**：MSI 48MHz → PLL(M=6) → SYSCLK 80MHz
（`main.c` 的 `SystemClock_Config`）。

**注意**：这不能推断 HSE 晶振是坏的 —— 那正是下面被排除的一条。

| **1** | **`C_p` / τ**（见二·补六） | 拉回后断开参考、立刻连续采样几百点，拟合指数 → `τ`。**与 160µs 比**：远小则无事，ms 量级则四处纯积分模式都要处理 |
| **2** | **`q` 用 `I₊` 自标**（需要"固定极性积分"模式，尚未实现） | `q` 应落在标称 `1.5259e-14 C/码` 的 ±5% 内（标称由 `100pF × 3.3V /(65536 × 0.33)` 三个猜的值相乘得出） |
| **3** | **拉回相**（目标已改成 0V） | `B` 回传波形**首点应 ≈ `code_zero`(30782)**，不再是 65520；开头饱和前缀为 0 |
| **4** | **拉回相搬进 ISR + 分母 `m+n`** | 结果行 `T=` 应为 **1000ms 整**；`RAW` 段的 `m+n` 应 = **6250**；连测两次同一电流应逐位相同 |
| **5** | **`RAW` 段** | `RAW m=.. n=.. INT1=.. INT2=.. EXT1=.. EXT2=..` 六个字段齐全；`INT1`/`EXT1` 是拉回最后一拍（V_01），不是 `voltage_buf[0]` |

### HSE 晶振电路

不改固件就能验：

```
mww 0x40021000 0x00010000     # RCC_CR: 置 HSEON (bit16)
mdw 0x40021000                # 读回: bit17(HSERDY)=1 即起振成功
```

复位即恢复，不影响 Flash 内容。起振则可以考虑把系统时钟换成 HSE
（比 MSI 准，对外部 ADC 时序和串口都更稳）。

### 测量数值全部待复测

`I_ref`、绝对增益、积分电容值、两路 ADC 一致性 —— 2026-09-11 记录过一批
数值，但未经独立复验。**当前策略：全部用 `current.h` 里的标称值计算**，
标定留到后续详细测试之后。标定值的落点就是 `current.h` 的宏，
**没有独立的拟合头文件**。

### 窗口计数与 ADG 相位

旧记录称 `m_count`/`n_count` 的窗口复位与 ADG 切换不同步、窗口长度 6250
不是周期（约 236 点）的整数倍 → 窗口刚重置时占空比读数严重失真。

**已解决（2026-09-12 重构）**：拉回相搬进了 TIM6 中断，窗口两端（`V_01` 与最后
一个窗口采样）都是 ISR 采样、采样偏移相同，计数覆盖的正好是它们之间的 6250 个
间隔。于是 `n_total = m+n = 6250`（**不用减一**）、窗口时长 = 6250×160µs =
**1.000 s 整**，论文的 `(m+n)` 形式精确成立。

**为什么"在主循环里拉回"不行**：那样 `V_01` 到采样点 0 的间隔是
`160µs + 读一次 ADC 的耗时 + 启动 TIM6 的代码延时`，比整一拍多出后两项。
残差公式：

```
误差 = I₊ · (C_ISR + δ) / 窗口时长
     = I₊ · (读一次的耗时 + 启动延时) / 1s
     ≈ 50nA × 12µs / 1s ≈ 0.6 pA   （恒定，但依赖编译结果，说不清来源）
```

**注意**：旧实现（在主循环里拉回、计数减一）**也是精确的** —— 它只要保证
"减的那一拍"减在开窗极性对应的计数器上。两者都对，区别只是新实现让分母直接
等于 `m+n`，报告里和论文对得上。

> **踩过的坑**：中途曾让开窗极性跟着拉回方向走（从上面拉就用 NEG、从下面拉就用
> POS），却仍固定减 `n_count`。那样等于**减错极性**，误差是
> `(I₊−I₋)/(N−1) = 100.5nA/6249 ≈ 16.1 pA`，而且**随开窗极性翻符号** ——
> 是噪声不是偏置，`a/b` 拟合吸收不了。比"用哪种分母"严重得多。

### 拉回相

为解决「窗口开头端点撞轨」（实测开头 38 个样本压在满量程）而加，
**尚未在硬件上确认有效**。验收判据：`B` 回传的波形**首点应 ≈ `code_zero`(30782)**
（拉到 0V 再开窗），不再是 65520；开头饱和前缀应为 0。

> 目标点位的选择：**拉到 0V 而不是某个阈值**。拉到边界是赌电流符号 ——
> 赌错那侧余量为 0、第一拍就撞轨；0V 则两个方向各留 4.3V，且第一个相位是
> 正常长度（停在阈值上会退化成 1 拍的相位）。

### 模式二只覆盖一个极性

上积相等待 `raw <= code_target`（原始码下降 = V_int 上升 = 与 I_POS **反号**的
电流），**正的小电流永远不触发** → 10 s → `HARD_TIMEOUT`。

## 六、调试教训（踩过的坑）

- **日志里的下标和环形缓冲对不上时，先怀疑计数器语义。**
  `ext_err_total` 从开机累加不清零，而环形缓冲每窗口重写 —— 日志里的下标在
  缓冲区里读到的是本窗口（更晚）的数据，两者本来就不该对应。
  **不要照这个去反汇编 `Current_Process`，纯属浪费时间。**
- **测出的"系数不对"先怀疑自己用的元件参数，再怀疑硬件。**
  早期算出「I_ref 只有 14.5nA、比标称小 3.44 倍」，根因是电容用了 30pF
  而实际是 100pF（3.44 × 30 ≈ 103 pF）。
- **不要拿早期会话写下的硬件诊断当事实引用。** 那些结论大多来自单一观察加
  推理，没有独立验证。引用时标注来源与日期，并优先用当前代码或实采数据复核。
